ISS-01

Checkout → Leaderboard ANR

Mitigation implemented · native retest pending
Reported behavior
Rapid Connect taps, Android Back and Leaderboard navigation produced a 5,112 ms input timeout on code27.
Diagnosis
Recovered the original Android ANR trace. The main thread was waiting inside Skia OpenGLWindowContext::present / eglSwapBuffers / SurfaceTexture frame delivery. This identifies the blocking stack; it does not prove which driver, recorder or scheduling condition initiated the stall.
Change
Unmount hidden game canvases and stop the frame callback during menus/checkout. Release the phone renderer while checkout covers it. Pause pass video while connecting. Coalesce concurrent Connect requests into one MWA transport; keep an explicit retry after rejection.
Actually tested
20 concurrent Connect requests → one transport (unit test). Ten game → checkout → game/menu cycles: 2 canvases → 0 → 2 each time. Ten phone → checkout → phone cycles: covered viewer unmounted and restored each time. No fresh browser console errors after the final export.
Still needs verification
The exact missing-wallet Android sequence must still be repeated 20 times, recorded and unrecorded, on code30 and a physical phone. This issue is not closed as an Android ANR fix.

ISS-02

Hideout grid leaves an empty column

Fixed · browser verified · Android retest pending
Reported behavior
At 1080×2400 / 420 dpi, Solana and Outfits wrapped to two narrow columns and left a large unused strip.
Diagnosis
Card width was calculated from the window, not the measured scroll-content width. Fractional Android density made three cards plus gaps overflow.
Change
Measure the actual grid container. Divide the space after both gaps by three and round down to whole physical pixels. Preserve all seven Solana skins, outfit cards and the fixed bottom action.
Actually tested
Outfits measured at 360, 393 and 412 CSS px: three columns fit. Solana verified at 412 and final 393 CSS px. Beeman remains selectable; its Equip action stays visible. The automated matrix covers five densities and six measured widths, including 2.625 density.
Still needs verification
Recheck Android Yoga layout at the report’s two physical resolutions and intermediate density. Browser measurements do not replace that check.

Evidence: web-grid-layout.json · client-tests.txt

ISS-03

Missing-wallet error is vague or inconsistent

Fixed in code · automated verification
Reported behavior
Pass and skin checkout showed a generic failure; Add Credits displayed a different/raw native error.
Diagnosis
The error classifier missed the MWA SDK code ERROR_WALLET_NOT_FOUND and its “Found no installed wallet…” message.
Change
One shared error view now serves credits, pass, skin and History connection. It explains that a compatible wallet is missing, tells the player to install/unlock Phantom and retry, and includes a Get Phantom link. Cancellation remains distinct from network failure.
Actually tested
Actual missing-wallet SDK code, native message variants, cancellation and network classification pass regression tests. Rapid requests and rejection/retry behavior pass. The APK includes the native implementation.
Still needs verification
No compatible wallet was installed or used. Native screenshots for all entry points, successful wallet handoff, signing and payment confirmation remain unverified.

Evidence: client-tests.txt · diagnostics.ts

ISS-04

History has no local Connect action

Implemented · native flow retest pending
Reported behavior
Disconnected History asked the player to connect a wallet but offered no Connect button in that view.
Diagnosis
The empty state was text only. The league refresh also swallowed interactive sign-in failures.
Change
History now offers Connect wallet / Sign in to view runs, waits for the selected account before sign-in, and displays retry/error recovery in place. Interactive league sign-in errors propagate to the view. It keeps the History tab mounted.
Actually tested
TypeScript and release bundle pass. Existing local browser history still renders its saved attempts. Browser preview uses a local account, so it does not exercise the native disconnected state.
Still needs verification
Connect, cancel, retry and real account-history retrieval require native wallet testing. Source review is not counted as a passed end-to-end connection test.

ISS-05

First phone preview shows an empty stage

Implemented · readiness tests pass · native visual retest pending
Reported behavior
Frost first opened with a blank area and rotation instructions before the model appeared.
Diagnosis
A decoded model and a few render callbacks did not guarantee phone geometry had reached a rendered frame.
Change
Show a phone poster and loading indicator. Hide/disable rotation controls until a rendered pick query confirms an entity belonging to the phone. Limit to one query in flight, stop after readiness or unmount, and handle released-view errors. After 15 seconds, use rendered turntable views with a Retry live 3D action.
Actually tested
Readiness tests cover empty/wrong entities, valid phone geometry, density conversion, overlapping queries, late callbacks after close and released native views. Frost renders in the browser; ten checkout cover/uncover cycles restore it.
Still needs verification
Cold-open all 12 native models on host-GPU emulator and physical hardware; verify the poster, first real frame, preset controls, timeout and retry. Browser Three.js is a different renderer from Filament.

Evidence: client-tests.txt · web-phone-checkout-cycles.json

ISS-06

SwiftShader black lower frame

Environment finding · physical verification pending
Reported behavior
The original code27 report captured a black lower tutorial frame with swiftshader_indirect. Its later host-GPU run did not reproduce it.
Diagnosis
Evidence is renderer-specific. The report does not establish the artifact on a physical Android GPU.
Change
Document host GPU (-gpu host) as the emulator QA baseline. Keep software-renderer results separate; do not lower physical-device rendering quality based on this emulator-only artifact.
Actually tested
The QA emulator was booted using host GPU. Code30 installed successfully with preserved data. Browser tutorial movement, cover and drone attack were exercised with a visible complete board.
Still needs verification
Code30 tutorial display and recording still require native UI testing, followed by physical Android verification. No claim is made that SwiftShader itself is fixed.

I

Summary

The game is a top-down tap-to-move stealth game rendered with React Native Skia on an Expo 55 shell. The rendering architecture was sound: a fixed 30 Hz simulation in a Reanimated worklet on the UI thread, interpolated drawing through Skia derived values, and no React render per frame. The slowness came from how that architecture was used, not from the engine. Six defects were confirmed by reading the code and the library sources, and all six were fixed on 2 October 2026 without touching the simulation rules, so the server replay verifier still accepts every run.

The decision to stay on React Native and Skia was taken on 2 October 2026 after comparing a renderer swap, a Godot, Unity or Flutter rewrite, and a hybrid native view. For a 2D game with fewer than ten moving guards every option reaches the Seeker's 120 Hz display; the current stack is the only one that keeps the server-verified simulation, the 396 passing tests and the first-party Solana Mobile wallet path, and it fit the six days left before the deadline.

What the evidence does not show

No physical phone has ever been profiled. Every Android frame number in the repository comes from an emulator, and every browser number from a desktop. The fixes below are confirmed by code and by the Reanimated and Skia sources, and the game was played end to end in a headless browser after each change, but the frame time on a Seeker or on the Realme RMX5033 remains unmeasured. Section VII explains how to measure it.

II

How a frame is produced

Time is driven by a Reanimated frame callback. Each display frame adds its delta to an accumulator and runs as many fixed 1/30 s steps as fit, capped at three so a slow frame cannot spiral. Drawing interpolates between the last two tick positions. Taps are written to a shared value by a gesture worklet and processed inside the frame callback at most once every 80 ms. Nothing in this loop touches React.

The React side receives a copy of the game state every 120 ms and on status changes. That copy drives the HUD, the coach text, audio hooks and the result sheets. Everything mounted under the game screen used to re-render on each of those publishes.

The Seeker runs a MediaTek Dimensity 7300 with a Mali-G615 GPU, 8 GB of memory and a 6.36 inch 2670 by 1200 display with 120 Hz dynamic refresh, per the Solana Mobile specification page (undated, checked 2026-10-02). A 2D scene with eight guards is light work for that part on any engine. The ceiling is the same for every option; the difference is how many new problems each one adds on the way there.

What would reopen the question: a device trace after these changes that still shows player-visible jank attributed to Skia raster or GPU submission rather than JS or UI thread work; a draw list that cannot fit the frame budget even with atlas batching; a product decision to move to the angled 3D view; an organiser APK size limit; or a Mali-G615 specific defect in Skia or Reanimated. None of these exists today.

About the in-app frame counter

The pause sheet shows fps, p95 and slow frames from the frame callback itself. It measures how often the callback fires, not how many frames the display presented, and it never counted the frames finding 1 discarded. Use adb shell dumpsys gfxinfo or a Perfetto trace for presented frames.

VII

What remains

Measure on a phone first

Install the code 36 APK on the Realme RMX5033 and, if one can be borrowed, on a Seeker. Record the baseline before judging anything else.

adb install -r releases/steal-a-seeker-mainnet.apk
adb shell dumpsys gfxinfo com.bluntbrain.stealaseeker reset
# play level 1 for two minutes, then level 11 with an active alarm
adb shell dumpsys gfxinfo com.bluntbrain.stealaseeker framestats > verification/perf/device-level1.txt
adb shell dumpsys meminfo com.bluntbrain.stealaseeker | head -40
# cold start
adb shell am force-stop com.bluntbrain.stealaseeker
adb shell am start -W com.bluntbrain.stealaseeker/.MainActivity

Acceptance: under 2 percent janky frames and p95 under 16.7 ms over a three minute level 11 run at 60 Hz, a stable 30 fps fallback only if pacing is even, cold start under 3 seconds, no ANR, and no growth in resident memory over a 15 minute session.

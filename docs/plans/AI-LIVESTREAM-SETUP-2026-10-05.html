I

The honest answer first

There are two different things people mean by "an AI plays the game", and the show should pick one on purpose. The first is a scripted brain: the game already ships a solver (scripts/qa-combat.ts) that reads a level, tries a handful of strategies and returns a winning sequence of taps in a few seconds. That is how every published level is proven winnable before anyone sees it. Fed into the real game at the right ticks, it plays the level live, visibly, and wins. The second is a language model with eyes and hands: a model such as Claude looks at screenshots and decides where to tap. That is genuinely "AI playing", but each decision takes seconds, guards move at 30 ticks a second, and it will die a lot. It is a fun side act, not a three hour main act.

I did not recognise "jev" as a model name. If you meant a specific model, tell me which; the plan below works with Claude (through the Agent SDK) for commentary and strategy, and with the game's own solver for the actual play. The recommendation is the hybrid Codex proposed on 4 October: scripted controls play, a language model talks and picks the next strategy, and the overlay says exactly that: "AI commentary, scripted controls".

What must stay true on screen

Bot runs never enter the real leaderboard or earn credits. The web preview already runs with a local account that does not submit runs; keep it that way, and show an exhibition score instead. Do not say the bot "learns". Do not loop an old clip and call it live.

II

How the pieces connect

Browser or emulator

Use the browser. The web build is the same game code, it already exposes a scripting hook (window.__SEEKER_MVP__ gives the live state and camera), it renders at 60 frames per second on a desktop, and the repo already has a Playwright script that opens the map, clicks a level, presses Play and reads the state (scripts/playtest-web-campaign.cjs). The Android emulator can show the real APK, but with a software GPU it runs at a fraction of the frame rate and taps have to go through adb. If you want the phone on screen, put the emulator in a small picture in picture while the browser carries the show, or film a real Seeker with a camera for the first and last level.

Why the solver and not a model for the taps

A tap decided by a language model costs seconds and money; the solver decides in milliseconds and is right. The model's value is in what it says, not where it taps. If you still want a model to tap for a segment ("Claude tries level 7 blind"), run that as a bounded side act with the model on screenshots and a 5 minute cap, and go back to scripted play afterwards.

IV

Getting the stream onto X

Checked against X and OBS documentation on 5 October 2026. Your account's actual access is the one thing a document cannot verify; do the private test first.

  1. The account needs X Premium or Premium+. Media Studio is limited to verified subscribers; Basic is excluded. Some third party guides report a review period after subscribing before live goes active, which X's own page does not state. Treat immediate access as unverified until the private test works.
  2. Open studio.x.com, then Producer. Sources, Create source, RTMP: name it, choose the region nearest the streaming computer, create it. Open the source and copy the RTMPS URL and the stream key. Treat the key like a password.
  3. In OBS: Settings, Stream, Service: Custom, paste the server URL and the key.
  4. OBS output: 1280 by 720 at 60 fps, H.264, bitrate 9,000 kbps (12,000 maximum), keyframe interval 3 seconds, audio AAC up to 128 kbps. 1080p is documented at 30 fps only; do not assume 1080p60.
  5. In Producer: Broadcast, Create Broadcast, pick the source, set the audience to Private, start OBS, check the preview, create. Run a 15 minute private test with the full show running.
  6. For the real run, create a Public broadcast and use its Post button so it appears on the timeline. Pin that post. A broadcast is limited to 24 hours; a three hour run fits in one.
  7. End with End in Producer, then stop OBS. OBS reconnecting does not recreate an ended broadcast; the watchdog has to alert you, not retry forever.

Alternative: OBS to Restream or StreamYard, which connect to X with an authorised app and forward the RTMP feed. X documents that third party delivery is allowed. It does not remove the Premium requirement.

V

Rules that apply

  • Disclosure. X's authenticity policy prohibits deceptive synthetic media and allows non deceptive uses. Put "AI commentary, scripted controls" in the title and the overlay. A blanket labelling mandate for AI game streams was not found; the label is the honest choice regardless.
  • Automation. The stream itself is fine. Do not let the show post, reply or follow from the account automatically; X requires prior written approval for AI powered reply bots and prohibits scripting the website. Posting the broadcast link is a human action.
  • Music. X processes copyright complaints and Premium includes no music licence. The game's two tracks were generated on ElevenLabs on 4 October 2026 (receipts in assets/music-spy-v2); confirm that the ElevenLabs plan's commercial terms cover live streaming and clips before the public run.
  • Sponsors. Third party advertising inside the video needs prior consent from X. No sponsor overlays for the first show.
  • Likeness. Boss levels show real people's faces and names. The same consent question as the marketing plan applies before a boss fight is streamed.

The shortest path to a first show

Build pieces 1 to 3 (autopilot, runner, exhibition guard), stream without commentary once in private, then add the overlay and Claude's voice for the public run. Two evenings of work before the first private test.

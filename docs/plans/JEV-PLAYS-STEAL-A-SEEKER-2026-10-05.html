I

What Jev is, and why that is good news

Jev is a "System One" decision model from TypeSafe AI, launched on 15 September 2026 (model id jev-1.13.0). You send it a state as JSON and a question with named options; it returns the option it picks, a probability for every option and a confidence. It does not write prose, and it does not look at pictures: text and JSON only. TypeSafe's own game demos feed it structured state, not frames. It is sold on speed: 70 to 500 milliseconds end to end, 80 requests per second, 64k tokens per request.

That sounds like a problem for "watch an AI play a game", and for most games it is. For this game it is the opposite. Steal a Seeker is a deterministic simulation whose whole state is already a JSON object: courier position and health, every guard's position, facing, cone, mode and health, the walls, the phone, the exit. The browser build exposes it on window.__SEEKER_MVP__.snapshot() for the test harness. And the controls are tap to move: a decision is "go there", not "press left for 40 milliseconds". So Jev can be the actual player, making every decision, and the honest label is "Jev decides, the game walks".

II

The decision loop

Why this is real play and not a puppet

The options offered to Jev are only the moves a finger could make right now: nodes it can walk to, guards it can reach, pockets it can hide in, or waiting. Nothing in the option list tells it which one is safe. Jev gets the same facts a player sees on screen: where the guards are and which way they face, their cone ranges, whether one has spotted you, your health, where the phone and exit are, and the walls. It does not get hidden guard intentions, where a guard will search next, or future randomness. If it walks into a cone, it dies, and the stream shows it. If it learns the rhythm of a patrol from the facts in front of it, that is the show.

The observation, concretely

Guards are listed only when the player could know about them: on screen, recently heard, or last seen. Walls are sent once per level and then referenced by level number so each decision stays around 1,000 to 1,500 tokens.

The question, concretely

{
  "model": "jev-1.13.0",
  "state": { "...the observation above..." },
  "questions": {
    "next_move": {
      "type": "choice",
      "instructions": "You are the courier in a stealth heist. Reach the phone, then the exit, without being caught. Guards see inside their cone, hear footsteps within 3 tiles, and search where they last saw you. Pick the next move.",
      "criteria": {
        "walk_north_2": "Walk 2 tiles north to (2.0, 15.4). Open corridor. Nearest cone edge 4.1 tiles.",
        "walk_east_2":  "Walk 2 tiles east to (4.0, 17.4). Enters guard 0's cone if he turns south.",
        "hide_pocket_a": "Step into the dead end at (0.9, 16.0). Out of every cone. Costs time.",
        "attack_guard_0": "Approach guard 0 from behind and slash. He faces away. 7.6 tiles away.",
        "wait": "Stand still for half a second and watch."
      }
    }
  }
}

Jev answers with the key of the option it chose, a probability for each option and a confidence. The overlay can show those probabilities live, which is the most interesting thing on screen: you watch it hesitate between "hide" and "attack".

III

Is it fast enough for this game

Thing that sets the paceValueWhat it means
Simulation tick30 per secondJev will never act per tick, and does not need to.
Courier walking speed3.2 tiles per secondA 2 tile move takes about 0.6 s, the natural decision interval.
Guard spot time0.5 s inside a conePlus a suspicion phase before that in the revision 17 engine. A 0.5 s reaction is tight but playable when moves are short.
Guard pursuit speed2.3 to 2.75 tiles per secondSlower than the courier; a spotted Jev can still escape if it chooses a corner.
Jev model time70 to 500 msTypeSafe's claim; our observation is larger than their demos, so plan on the upper half.
Round trip India to US west coastabout 300 msMeasured today against our own Railway service in San Francisco; TypeSafe's region is unverified.
Decision interval, realistic350 to 800 ms2 to 3 decisions per second. Enough for 2 tile moves, not enough for frame perfect dodging.

Two design rules make this work. First, move lengths match the latency: offer 1.5 to 2.5 tile moves so a decision is executing while the next one is in flight. Second, reflexes stay in code, and are disclosed: when a guard's cone reaches the courier, the option list collapses to escape routes for the next decision and the overlay says "danger options only". Jev still chooses which escape. No code moves the courier on its own.

If TypeSafe's region makes the round trip longer than expected, run the show computer on a US west coast machine or stream from one; the X encoder does not care where the browser runs.

Order

Pieces 1 to 5 first, in that order, which is about three days. The evaluation decides everything else: if Jev clears most of the first thirty levels, the show is "Jev versus the campaign". If it dies constantly, the show is "Jev versus the solver" on the same seeds, which is funnier and still honest.

V

Show formats the numbers can support

  • The run. Jev plays level 1 to 100 in order. Deaths restart the level; a level is skipped after five deaths with a marker on the overlay. Expected length is unknown until the evaluation; a human needs about three hours, Jev may need more.
  • Jev versus the solver. Split screen, same level, same seed. The solver's run is deterministic and already proven; Jev's is live. Score both on the exhibition board. Best for the first stream because it always has something to show.
  • Chat picks the room. Replies choose the next level number from the thousand published rooms; Jev plays it. Automation of the account is not involved; a human reads the replies and types the number.
  • Boss nights. The seven arenas in a row, with the boss trait on the overlay and Jev's probabilities visible as it decides to attack or hide. Needs the consent of the people the bosses are based on, as in the marketing plan.

# Haptics: a vocabulary the thumb can read

Plan written 4 October 2026 for the hunter-stealth branch. Target device: Solana Seeker (Android, standard vibration motor). Implemented the same day, see section 6.

## 1. What the player feels today

- Every Android cue goes through `View.performHapticFeedback` (expo-haptics `performAndroidHapticsAsync`). Those system constants are short, quiet, and vanish entirely when the phone's "touch feedback" setting is off. A knife kill is `Context_Click`, the same effect as a tap on a UI button.
- Floor taps produce no haptic. Target taps produce none either; only menu buttons tick.
- Combat cues are derived from the 120 ms HUD snapshot in `useCombatAudio`, so a hit can buzz up to 120 ms after the frame shows it.
- There is no texture difference between a knife hit, a takedown, a boss takedown and damage taken.

## 2. Principles

1. A haptic answers either a player action (tap, start, buy) or a state change the player must notice without looking (hit, kill, damage, spotted, pickup, exit charging, win, caught). Ambient AI noise never vibrates.
2. Three tiers with distinct textures, so the thumb can tell them apart blind:
   - Tick: one short soft pulse, barely there. Tap acknowledgement, map node, exit charging, suspicion.
   - Thump: one firmer pulse. Knife hit, pickup, switch, armor clank, start.
   - Pattern: a rhythm at the motor's default strength. Kill, stealth kill, boss kill, damage, spotted, win, caught. Rhythm carries meaning: a kill is "thud, tick", a boss kill is three rising beats, damage is a sharp double, caught is one long fall.
3. Timing is tick accurate. Combat cues fire from the simulation step on the UI thread, not from the HUD snapshot. A tap is acknowledged in the frame its command resolves.
4. Priority and restraint. Patterns cancel any pending lower sequence; ticks never delay a pattern; every cue has a minimum gap; spotted and suspicion have long gaps so a nervous guard cannot buzz the hand continuously.
5. Always on. Vibration is part of the controls, like the tap itself, so there is no setting to turn it off (decision by the user on 4 October). Background and web are silent. Menus and pause produce only UI ticks.
6. Tunable on the device. The Settings sheet keeps a "Try it" row that plays a tick, a hit, a takedown and damage, so the feel can be judged on a Seeker without playing.

## 3. Primitives available without native code

| Primitive | Android behaviour | Use |
| --- | --- | --- |
| `expo-haptics impactAsync(light)` | one 50 ms pulse at amplitude 30 of 255 | Tick |
| `impactAsync(medium)` | one 43 ms pulse at amplitude 50 | Thump |
| `impactAsync(heavy)` | one 60 ms pulse at amplitude 70 | Firm thump |
| `react-native Vibration.vibrate([wait, on, wait, on, ...])` | waveform at the device default amplitude, cancellable | Patterns |
| `performAndroidHapticsAsync(...)` | system view feedback, honours the touch-feedback setting | Fallback only |

Amplitude control beyond this needs a native module (`VibrationEffect.createWaveform` with amplitudes). Not needed for the vocabulary above.

## 4. The vocabulary

| Cue | Tier | Waveform (ms) | Source | Gap |
| --- | --- | --- | --- | --- |
| tapMove | Tick | light | tap resolves to a move | 60 |
| tapTarget | Tick+ | medium | tap resolves to attack, phone, switch or exit | 60 |
| blocked | Tick ×2 | [0,18,40,18] | tap resolves to nothing, route blocked | 250 |
| select | Tick | light | menu buttons, map nodes | 90 |
| start | Thump | heavy | Play | 250 |
| confirm | Pattern | [0,30,50,45] | purchase, equip, claim done | 350 |
| error | Pattern | [0,35,45,35] | failed purchase, locked node | 350 |
| melee | Thump | medium | knife hit that does not kill | 120 |
| armor | Thump ×2 | [0,25,35,45] | front hit on armour | 200 |
| kill | Pattern | [0,45,55,22] | guard down | 180 |
| stealthKill | Pattern | [0,28,70,60] | rear takedown of an unaware guard | 180 |
| bossKill | Pattern | [0,55,65,55,65,95] | boss down | 400 |
| damage | Pattern | [0,45,45,45] | health lost | 180 |
| pickup | Thump | heavy then light at 70 ms | phone taken | 350 |
| exitTick | Tick | light | extraction passes 25, 50, 75 percent | 150 |
| switch | Thump | medium | switch or relay used | 250 |
| spotted | Pattern | [0,24,55,24] | a guard confirms the courier | 1500 |
| suspicion | Tick | light | a guard turns suspicious | 1200 |
| success | Pattern | [0,30,65,45,65,85] | extraction complete | 700 |
| caught | Pattern | [0,110,70,210] | health gone | 700 |
| claim | Thump | heavy | credits flying | 700 |
| coin | Tick | light | each credit coin landing in the claim animation | 110 |
| dash, decoy | Tick | light | legacy levels | 250 |

Priority order, high to low: caught, success, bossKill, damage, kill, stealthKill, spotted, confirm, error, pickup, claim, start, switch, armor, melee, tapTarget, blocked, suspicion, exitTick, select, tapMove, dash, decoy. A cue of lower or equal priority within 90 ms of the last one is dropped; a higher one plays and cancels a running waveform.

## 5. Where the cues come from

- `src/GameScreen.tsx` frame worklet, after each simulation step: kills, hit events and blocks from the combat counters; damage taken; carrying, status, power and relay changes; guards switching to hunting (spotted) or suspicious; extraction thresholds. The tap branch classifies the resolved command.
- `useCombatAudio` keeps its sounds and stops emitting haptics, so nothing fires twice.
- UI: `HapticPressable` default is `select`; the level map uses `select` for open nodes and `error` for locked ones.
